# Automated Product Description Generation From Images

This project is a coursework prototype for generating marketplace-style product descriptions from a product image and optional trusted catalog facts. The final system is a neural pipeline:

```text
product image -> BLIP visual caption
product image -> optional OCR visible text
optional title/metadata -> trusted product facts
all evidence -> FLAN-T5-base LoRA v3 writer -> generated description
```

BLIP provides visual evidence and OCR can recover visible brand or model text. The final description is generated by the FLAN-T5 writer rather than assembled from templates.

## Current Final Version

The demonstrated and evaluated pipeline uses:

- BLIP visible-caption adapter: `outputs/lora_adapter_description_v2`
- neural writer adapter: `outputs/text_writer_flan_t5_base_lora_neural_marketplace_v3`
- writer prompt style: `complete`
- optional OCR backend: EasyOCR

On the complete held-out test split of 1,668 Amazon products, the v3 writer obtained token F1 of `0.243`, used recognized OCR terms in `55.0%` of applicable examples, and produced no prompt artifacts in the automatic checks. Generated copy is a draft: unsupported material or performance claims may still occur and should be reviewed before publication.

## What Is Included

- A reproducible early BLIP adaptation stage on fashion images.
- Amazon bestseller dataset preparation from product metadata and image links.
- Cached BLIP/OCR evidence generation followed by a v3 rebuild with safer missing-metadata variants.
- Neural description generation from image evidence and optional user-supplied facts.
- Automatic comparison checks for overlap, OCR use, repetition, prompt artifacts, colors and product type.
- Training configured for a CUDA machine such as an RTX 3070 Ti.

## Early BLIP Visual Adapter Stage

Expected raw Kaggle layout:

```text
data/raw/styles.csv
data/raw/images/1163.jpg
data/raw/images/1164.jpg
...
```

Create image-only description targets:

```bash
python -m src.prepare_dataset \
  --styles_csv data/raw/styles.csv \
  --image_dir data/raw/images \
  --out_dir data
```

The default `target_style=description` builds conservative one-sentence references from visually grounded fields, for example color and product type:

```text
A grey t-shirt.
```

Other target styles:

- `--target_style visual`: short labels such as `blue jeans`; useful only as a grounding check.
- `--target_style title`: product titles from `productDisplayName`.
- `--include_category_in_description`: adds a second category sentence. This is disabled by default because it can make the model repeat category templates.
- `--include_catalog_details`: adds metadata such as audience and usage. Use for metadata-assisted experiments, not the image-only baseline.
- `--include_title_in_description`: adds `productDisplayName`. Use only when product titles will also be available at inference time.

### Train Description LoRA

Good first run for an RTX 3070 Ti:

```bash
python -m src.train_lora \
  --train_jsonl data/train.jsonl \
  --val_jsonl data/val.jsonl \
  --out_dir outputs/lora_adapter_description_v2 \
  --batch_size 8 \
  --grad_accum 4 \
  --epochs 3 \
  --lr 2e-4 \
  --max_train_steps 2000 \
  --max_length 64 \
  --num_workers 4
```

Generate LoRA predictions:

```bash
python -m src.predict \
  --jsonl data/val.jsonl \
  --adapter outputs/lora_adapter_description_v2 \
  --out outputs/predictions/val_lora_description_v2_noprompt.jsonl \
  --limit 300 \
  --batch_size 8 \
  --max_new_tokens 40
```

The fine-tuned adapter is trained without a decoder prompt, so prediction also runs without a prompt by default. If you experiment with prompts, compare them carefully; BLIP can become noticeably worse when the prompt style does not match fine-tuning.

Evaluate the LoRA run:

```bash

  --preds outputs/predictions/val_lora_description_v2_noprompt.jsonl \
  --out_metrics outputs/metrics_lora_description_v2_noprompt_300.json \
```

## Neural BLIP + OCR Text Writer

This is the final project pipeline. BLIP and OCR are feature extractors, while the text writer generates the final marketplace description from product facts.

Prepare neural writer rows from the improved Amazon dataset:

```bash
python -m src.prepare_neural_writer_dataset \
  --input_jsonl data/amazon_bestsellers_improved/train.jsonl \
  --out data/writer_amazon_neural/train.jsonl \
  --image_adapter outputs/lora_adapter_description_v2 \
  --caption_mode blip \
  --ocr \
  --ocr_backend easyocr \
  --easyocr_gpu auto \
  --ocr_batch_size 4 \
  --max_target_chars 450

python -m src.prepare_neural_writer_dataset \
  --input_jsonl data/amazon_bestsellers_improved/val.jsonl \
  --out data/writer_amazon_neural/val.jsonl \
  --image_adapter outputs/lora_adapter_description_v2 \
  --caption_mode blip \
  --ocr \
  --ocr_backend easyocr \
  --easyocr_gpu auto \
  --ocr_batch_size 4 \
  --max_target_chars 450

python -m src.prepare_neural_writer_dataset \
  --input_jsonl data/amazon_bestsellers_improved/test.jsonl \
  --out data/writer_amazon_neural/test.jsonl \
  --image_adapter outputs/lora_adapter_description_v2 \
  --caption_mode blip \
  --ocr \
  --ocr_backend easyocr \
  --easyocr_gpu auto \
  --ocr_batch_size 4 \
  --max_target_chars 450
```

Each writer row contains:

- `input_text`: title/category/metadata plus BLIP visible caption and cleaned OCR text;
- `target_text`: the original marketplace description target;
- `facts`: the factual inputs sent to the writer;
- `ocr`: raw and cleaned OCR details.

When no brand metadata is provided, the pipeline can infer common brands from OCR/title text using a small exact-match brand lexicon. This is intentionally conservative: it helps with visible names such as `adidas` or `DEWALT` without doing expensive fuzzy guessing.

This extraction stage is deliberately run without random metadata dropout for the v3 workflow. Missing-metadata variants are produced by the cached rebuild below, where fields used by the real reference description are preserved.

### Fast V3 Writer Rebuild

Once `data/writer_amazon_neural/*.jsonl` already exists, do not rerun BLIP or OCR just to create v3 inputs. The cached rebuild path reuses stored captions, OCR, metadata, and targets, but it is not only a speed shortcut: it defines the final v3 prompt and safer training-row filtering:

```bash
python -m src.rebuild_neural_writer_dataset \
  --input_jsonl data/writer_amazon_neural/train.jsonl \
  --out data/writer_amazon_neural_v3/train.jsonl \
  --summary data/writer_amazon_neural_v3/train_summary.json \
  --prompt_style complete \
  --safe_dropout_variants 1

python -m src.rebuild_neural_writer_dataset \
  --input_jsonl data/writer_amazon_neural/val.jsonl \
  --out data/writer_amazon_neural_v3/val.jsonl \
  --summary data/writer_amazon_neural_v3/val_summary.json \
  --prompt_style complete

python -m src.rebuild_neural_writer_dataset \
  --input_jsonl data/writer_amazon_neural/test.jsonl \
  --out data/writer_amazon_neural_v3/test.jsonl \
  --summary data/writer_amazon_neural_v3/test_summary.json \
  --prompt_style complete
```

The `complete` prompt asks for natural sentences instead of an "Amazon-style" format. The rebuild ignores old random-dropout copies and drops a small set of field-list targets such as descriptions beginning with `Material:` or `Size and Packs -`. An experimental `--supported_sparse_variants` option exists, but it is not recommended for the first v3 run because noisy BLIP captions can still make sparse supervision unreliable.

Train the v3 neural writer:

```bash
python -m src.train_text_writer \
  --train_jsonl data/writer_amazon_neural_v3/train.jsonl \
  --val_jsonl data/writer_amazon_neural_v3/val.jsonl \
  --model google/flan-t5-base \
  --out_dir outputs/text_writer_flan_t5_base_lora_neural_marketplace_v3 \
  --batch_size 1 \
  --grad_accum 8 \
  --epochs 1 \
  --max_train_steps 3000 \
  --max_input_length 384 \
  --max_target_length 128 \
  --lr 3e-4 \
  --warmup_steps 200 \
  --precision fp32 \
  --use_lora \
  --lora_r 8 \
  --lora_alpha 16 \
  --gradient_checkpointing
```

Generate writer predictions:

```bash
python -m src.predict_text_writer \
  --jsonl data/writer_amazon_neural_v3/test.jsonl \
  --model outputs/text_writer_flan_t5_base_lora_neural_marketplace_v3 \
  --out outputs/predictions/test_neural_marketplace_v3_full.jsonl \
  --local_files_only
```

Generate a single product description from a new image and title:

```bash
python -m src.generate_neural_description \
  --image "Q:\test.jpg" \
  --title "Permatex 81158 Black Silicone Adhesive Sealant, 3 oz. Tube" \
  --brand "Permatex" \
  --category "Automotive > Sealants" \
  --ocr \
  --local_files_only
```

The command uses the final v3 writer and `complete` prompt style by default. Supplying `--title`, `--brand`, `--material` or other optional facts lets the generator incorporate trusted user knowledge; omitting them keeps image-and-OCR-only inference available.
If a sparse optional field causes the writer to collapse into a field fragment, the inference safeguard may try a second generation, but it will not accept a retry that drops a trusted supplied attribute.

Create a lightweight comparison report from the current prediction files:

```bash
python -m src.compare_generation_runs \
  --run test_v3=outputs/predictions/test_neural_marketplace_v3_full.jsonl \
  --out_json outputs/neural_v3_test_full_vs_200.json \
  --out_md outputs/neural_v3_test_full_vs_200.md
```

The checks are automatic triage signals rather than proof of factual correctness. Use them alongside manual review of product type, visible attributes, OCR use, metadata use, hallucination, fluency and usefulness as product-page copy.

## Amazon Metadata Preparation

The UCSD Amazon metadata format usually includes both `asin` and `imUrl`. Bestseller-style datasets may instead include a product URL, a product name, an extracted description, and one or more image links. The preparation script supports both styles.

If a row contains direct `m.media-amazon.com` image URLs, including URLs embedded inside an extracted image block such as `colorImages`, the script will use those URLs directly. It also tries higher-resolution variants by removing Amazon size tokens such as `_SX522_` or `_SL1024_`, then keeps the row only if the downloaded image passes the minimum-size check.

Do not use this script as an Amazon product-page crawler. Prefer direct image URLs already present in the dataset, extracted fields you are allowed to use, or an official API route.

Prepare a small fashion-focused experiment:

```bash
python -m src.prepare_amazon_dataset \
  --metadata_path data/raw/amazon/metadata.json.gz \
  --out_dir data/amazon \
  --image_dir data/amazon/images \
  --download_images \
  --category_filter Clothing \
  --category_filter Shoes \
  --limit 1000
```

This writes `data/amazon/train.jsonl`, `data/amazon/val.jsonl`, `data/amazon/test.jsonl`, and `data/amazon/amazon_dataset_summary.json`. Each row keeps the local `image_path`, original `image_url`, `asin`, title, brand, category, and a cleaned `text`/`target_text` field for training.

Prepare a bestseller CSV with product-page URLs and embedded/direct image links:

```bash
python -m src.prepare_amazon_dataset \
  --metadata_path data/raw/amazon_bestsellers.csv \
  --out_dir data/amazon_bestsellers \
  --image_dir data/amazon_bestsellers/images \
  --download_images \
  --min_image_side 224 \
  --limit 1000
```

Common column names such as `Product URL`, `Product Name`, `Image URL`, `Image Block`, `Description`, `Brand`, `Category`, and `Price` are handled automatically.

For the local bestseller dataset currently used in this workspace:

```bash
python -m src.prepare_amazon_dataset \
  --metadata_path "Q:\E-commerce\data\github_bestsellers\ecommerce-product-dataset-main\data\amazon_com\best_sellers\amazon_com_best_sellers_2025_01_27.csv" \
  --out_dir data/amazon_bestsellers_improved \
  --image_dir data/amazon_bestsellers/images \
  --download_images \
  --target_mode description_only \
  --prefer_features \
  --min_image_side 224 \
  --max_target_words 80 \
  --category_exclude Books \
  --category_exclude "Kindle Store" \
  --category_exclude "CDs and Vinyl" \
  --category_exclude "Audible Books" \
  --category_exclude Software \
  --category_exclude "Movies and TV"
```

The script understands the dataset columns `imageUrls`, `url`, `name`, and `description`. It can also use optional fields such as `brandName`, `breadcrumbs`, `salePrice`, and `listedPrice` when present.

## Notes For The Report

BLEU and ROUGE are useful for comparing runs, but they do not fully measure whether a description is truthful with respect to the image. Use the diagnostics Markdown file for manual inspection of failure cases:

- hallucinated attributes;
- incorrect product category;
- missing color or product type;
- overly generic text such as `the product`;
- label-like output that is too short for product-page copy.

The system developed in stages:

1. A fashion-oriented BLIP adapter established useful visual product captioning, but did not generate rich listing text.
2. Amazon images and real descriptions supplied marketplace-style supervision.
3. BLIP captions, OCR and optional trusted fields became evidence for a separate neural writer.
4. The final FLAN-T5 LoRA v3 writer generates the description, while automatic checks and manual review expose remaining hallucination risk.
